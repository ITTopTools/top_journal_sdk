# Контракты моделей

Все методы контроллеров v1/v2 возвращают Pydantic-модели, списки моделей,
скаляры либо явно обозначенный сырой HTTP-ответ. Ответы v2 больше не имеют
публичных типов `dict[str, Any]` / `list[dict[str, Any]]`.

## Сохранность данных

Модели ответов наследуют `APIModel`: известные поля валидируются, дополнительные
поля сохраняются с типом `JsonValue` (JSON-скаляры, списки и вложенные объекты).
Новые поля сервера сохраняются и в `model_dump()` / `model_dump_json()`.
Это относится и к вложенным моделям. Модели запросов не используют этот режим.

Для воспроизведения только присланных полей используйте
`model_dump(mode="json", by_alias=True, exclude_unset=True)`. Без `exclude_unset`
Pydantic также добавит значения полей по умолчанию.

## Подтверждённые и частичные схемы

Оценки занятий и поля документов v2 сверены с непустыми ответами API.
Поля будущих экзаменов, напоминаний, обращений поддержки, модерации документов
и причины отклонения профиля также сверены с кодом действующего фронтенда.

`UnconfirmedResponse` явно обозначает частичную либо ещё не наблюдавшуюся схему.
Для неё гарантированы проверка допустимых JSON-типов и сохранность полей,
но не полнота предметного описания. Отсутствующие поля не выдумываются.

В v1 это контакты преподавателей, будущие экзамены, четвертные оценки,
родственники, события месяца, сигналы и частично точки графиков.
В v2 частичны сигналы/обращения поддержки; состав подтверждений смены группы
и откладывания напоминаний ещё не наблюдался. Дополнительные настройки вариантов
документа представлены как `dict[str, JsonValue]`.

## Изменения интерфейса v2 в 0.4

| Метод / поле | Тип / использование |
|---|---|
| `dashboard.get_lesson_evaluations()` | `LessonEvaluationsResponse`, записи в `.items`, время запроса в `.meta.requested_at` |
| `profile.get_documents_fields()` | `DocumentFieldsResponse`, поля в `.fields` |
| `dashboard.get_support_requests()` | `list[SupportRequest]` |
| `profile.change_group()` | `ChangeGroupResponse`, сохраняет поля подтверждения, допускает пустой ответ 204 |
| Даты посещаемости, прогресса, расписания, рождения и следующей оплаты | `datetime.date` / `None` там, где поле допускает null |
| Дата активности и `requested_at` | `datetime.datetime` |
| Время начала/окончания занятий | `datetime.time` |
| `email_confirmation`, `opened_interview` | Модели объектов либо `None`; поддерживаются snake_case и camelCase счётчиков |
| `decline_comment` | `DeclineComment`, строка для совместимости либо `None` |
| `DocumentField.moderation` | `DocumentModeration` либо `None` |

Даты и время сериализуются в JSON через `model_dump(mode="json")` или
`model_dump_json()`. Для дальнейшей работы со словарём используйте эти методы
вместо прежнего индексирования ответа `response["items"]`.

`dashboard.delay_email_confirmation()` выполняет POST без тела,
`dashboard.delay_interview(interview_id)` — POST с `{"id": interview_id}`.
Они изменяют состояние напоминаний. Старые имена `get_startup_delay_*` оставлены
как совместимые обёртки, но тоже выполняют POST; для интервью обязателен ID.
Эти операции и смена группы проверяются на моках, без изменения live-аккаунта.

## Проверки

В `tests/fixtures/model_samples.json` хранятся синтетические непустые примеры
для каждого публичного класса модели. Тест сверяет список классов с примерами:
новую модель нельзя добавить без контракта. Примеры не содержат данных аккаунта.

Проверяются JSON-сериализация, алиасы, вложенные структуры, новые поля API,
неверные типы и даты, отсутствие обязательных полей, nullable-значения,
ненулевые объекты модерации/напоминаний, поиск занятий и счётчики домашних работ.
Проверка всех моделей не означает перебор всех возможных значений каждого поля.

Live-тесты v2 дополнительно проверяют ответы реального API. Пустой live-список
не считается подтверждением структуры его элементов. Live-проверка v1 зависит
от доступности сайта за DDoS-Guard.
